# Практическое задание №1
## Анализ технической документации и кейса интеграции

### Выбранный кейс

**Кейс Б. Агрегатор служб доставки.**

Разрабатываемая система представляет собой логистический модуль интернет-магазина, который взаимодействует с внешними сервисами транспортных компаний.

Для интеграции рассматриваются API следующих логистических операторов:

- СДЭК;
- Почта России.

Система получает информацию о заказах покупателей, передает необходимые данные во внешние сервисы доставки и получает информацию о текущем статусе отправления.

### Цели интеграции

Основными целями интеграции являются:

1. Автоматизация передачи данных о заказах в службы доставки.
2. Получение информации о стоимости и сроках доставки.
3. Получение трек-номеров отправлений.
4. Автоматическое получение актуальных статусов доставки.
5. Передача полученных статусов во внутреннюю CRM интернет-магазина.
6. Снижение количества ручных операций при работе сотрудников с заказами.

### Уровни интеграции

В данном проекте используются следующие уровни интеграции:

#### Уровень бизнес-логики

Логистический модуль интернет-магазина обрабатывает данные заказа, определяет выбранную службу доставки, формирует запрос и обрабатывает полученный ответ.

На уровне бизнес-логики выполняются:

- проверка данных заказа;
- расчет параметров отправления;
- выбор транспортной компании;
- обработка статусов доставки;
- передача информации во внутреннюю CRM.

#### Уровень программных интерфейсов

Для взаимодействия со сторонними сервисами используются внешние API транспортных компаний.

Бэкенд-сервис отправляет HTTP-запросы к API СДЭК и Почты России и получает ответы в структурированном формате.

---

## Источники данных

Основным источником данных является форма оформления заказа на сайте интернет-магазина.

Из формы могут поступать следующие данные:

- ФИО клиента;
- номер телефона;
- адрес электронной почты;
- адрес доставки;
- город;
- почтовый индекс;
- состав заказа;
- стоимость заказа;
- вес и размеры отправления;
- выбранная служба доставки.

Дополнительным источником данных является внутренняя информационная система интернет-магазина, содержащая сведения о заказах.

---

## Приемники данных

Приемниками данных являются:

### API транспортных компаний

Данные о заказе передаются во внешние информационные системы:

- СДЭК;
- Почта России.

Операторы доставки получают сведения, необходимые для регистрации и обработки отправления.

### Внутренняя CRM

CRM интернет-магазина получает:

- трек-номер;
- статус отправления;
- дату изменения статуса;
- расчетную дату доставки;
- информацию о доставке заказа клиенту.

---

## Транспортные протоколы и форматы данных

Для взаимодействия со сторонними API используется протокол:

**HTTPS**

HTTPS обеспечивает защищенную передачу информации между логистическим модулем и внешними сервисами.

Основным форматом передачи данных является:

**JSON**

Пример данных заказа:

```json
{
  "orderId": 1030,
  "customer": {
    "name": "Никита Корнышев",
    "city": "Санкт-Петербург"
  },
  "delivery": {
    "provider": "CDEK",
    "weight": 2.5
  }
}
```
